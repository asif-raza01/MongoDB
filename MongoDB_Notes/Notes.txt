Database->Physical layer where data actually gets stored.
Database Management System->An application or software whhich is used to manage the database.

DBMS types:
1.RDBMS
2.NoSql DBMS

RDBMS:
1.STORES DATA IN FORM OF TABLES(ROWS AND COLUMN).
2.TRANSACTIONS
3.FIXED SCHEMA

NOSqlDBMS:
1.KEY-VALUE
2.DOCUMENT(MONGODB USES THIS JSON LIKE(BSON))
3.COLUMNAR
4.GRAPHDB


MONGODB:
1.FREE OPENSOURCE STORES DATA IN JSON LIKE FORMAT(BSON)
2.FLEXIBLE SCHEMA DOES NOT REQUIRES FIXED SCHEMA
3.MONGODB ALSO LET US STORE RELATED DATA INSIDE SAME DOCUMENT USING EMNEDDED FIELDS.
4.MOST IMPORTANT SCALABLE OFFERS BUILT IN SCALING WITH MONGODB ATLAS WHICH IS SIMPLE

SCALING ->BASICALLY IMPROVING LOAD 
NOW VERTICAL SCALING INCREASING THE POWER EG. CPU RAM STORAGE OF A SINGLE SERVER ->LIMITATION IT CAN BE DONE ONLY TO CERTAIN EXTENT
HORIZONTAL SCALING INCREASING THE NUMBER OF SERVERS MONGODB HANDLES IT USING SHARDING AND REPLICA OF DATA

SHARDING IS BASICALLY SPLITTING OF DATA TO ACROSS MULTIPLE SERVERS
EACH SERVER WHICH IS SHARD NOW HOLDS A PORTION OF DATA
HELPS IN HANDLING LARGE WRITE LOADS
IMPROVES PERFORMANCE AND STORAGE AS THE DATA GROWS

REPLICA SETS IN MONGODB BASICALLY HAVING A COPY OF SAME DATA ON MULTIPLE SERVERS
USED FOR HIGH AVAILABILITY DATA REDUNDANCY AND FAILOVER SUPPORT WHICH EVEN IF ONE SYSTEM FAILS THERE IS OTHER FOR THE DATA
HELPS IN REDUCE HEAVY READ LOAD BEACAUSE THE SAME DATA CAN BE READ FROM DIFFERENT SERVERS
BUT NOT IDEAL FOR HEAVY WRITE OPERATION WHY? BEACAUSE EVERY WRITE MUST BE REPLICATED IN ALL COPIES FOR MAINTAINING CONSISTENSY

DATA MODELLING MEANS HOW TO ORGANISE YOUR DATA USING COLLECTIONS AND DOCUMENTS.
FOR A SINGLE COLLECTION WE CAN HAVE DIFFERENT TYPE OF DOCUMENTS.

THERE ARE TWO MAIN WAYS TO SHOW RELATIONSHIP BETWEEN DATA IN MONGOOSE
1.EMBEDDED DATA->WHEN WE TRY PUT WHOLE DATA IN A SINGLE DOCUMENT USING NESTED DOCUMENTS MORE COMPLEX EAGER LOADING
2.REFRENCES->CONNECTS DATA BY LINKING ONE DOCUMENT TO ANOTHER LESS COMPLEX ON DEMAND DATA THIS IS CALLED LAZY LOADING
